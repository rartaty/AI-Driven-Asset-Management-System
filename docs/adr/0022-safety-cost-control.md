# ADR-0022: コスト異常を起点とした安全・コスト制御

- **Status**: Accepted
- **Decision**: A-0、A-1、A-2の順で、外部呼出と監査性の安全基盤を先に固める。

## 観測した問題

実際のコスト異常を起点に、意図しないLLM実呼出、Discord webhook、API rate limit、429応答とbackoff不足、テスト分離不足、監査性不足という抜け穴を洗い出した。

## Engineeringの流れ

**障害・コスト事故を観測 → 原因仮説 → Control設計 → 実装 → Regression Test**

- **A-0**: テスト時の外部LLM・通知を抑止し、テストを外部状態から隔離する。
- **A-1**: APIごとのrate limit、429処理、指数バックオフ、timeoutを導入する。
- **A-2**: 実行状態、抑止理由、コスト関連イベントを記録し、後から検証できるようにする。

安全性を機能追加より先に整備することで、障害時に意図しない外部呼出やコスト増加が連鎖しない設計を目指す。
