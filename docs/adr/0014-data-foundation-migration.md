# ADR-0014: データ基盤の段階的移行

- **Status**: Accepted
- **Decision**: SQLiteからPostgreSQL、TimescaleDB、Parquetを組み合わせる構成へ移行する。

## 背景

個人ローカル運用の初期段階では、SQLiteは導入が容易で運用負荷も低く、合理的な選択だった。後からtickデータ量、同時書き込み、JSONBを用いる柔軟な検索という要件が加わり、単一ファイルDBでは継続が難しくなった。

## 比較

- **SQLite継続**: 導入は簡単だが、並行処理と時系列データ増加への適性に限界がある。
- **標準PostgreSQL**: 並行書き込みとJSONB検索に適するが、時系列最適化は追加で必要。
- **Parquetのみ**: 安価な長期保存には適するが、オンライン更新・検索の主基盤には不向き。
- **DBaaS**: 運用負荷を下げられるが、個人ローカル運用のコスト・接続要件に合わない。

## 決定

PostgreSQLを業務データの主基盤、TimescaleDBを時系列データの補助、Parquetを長期アーカイブに用いる。これにより、オンライン更新と分析用保存を分離する。
