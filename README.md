# Project Big Tester

**Project Big Tester** は、銀行・証券の資産情報、ポートフォリオ、資産推移、システム状態を統合し、AI支援とリスク管理を組み合わせてローカル環境で運用する個人向け資産管理・自動運用プラットフォームです。

本リポジトリは、実システムの構成・技術・安全設計を確認できる**サニタイズ済み技術公開版**です。生成されたデモではなく、実プロジェクトから公開可能な実装を選別しています。

> **公開方針**: 個人情報、実データ、認証情報、外部接続設定、銘柄選定・売買判断・配分・閾値・発注のロジックは含めません。

---

## 実際のProject Big Testerの機能

### 資産管理と可視化

- 銀行・証券の残高、保有状況、評価損益、資産推移をダッシュボードで統合表示します。
- ポートフォリオ、分析、監視、レポート、タイムラインを用途別の画面として提供します。
- 資産状態、システム状態、運用上のイベントを記録し、確認できる設計です。

### 自動運用の基盤

- 市場時間や処理状態に応じたスケジューラで、データ取得・状態更新・分析・レポート作成を実行します。
- 仮想取引と実運用の経路を分離し、運用モードを明示的に管理する設計です。
- 複数の時間軸・目的を持つ運用枠を扱い、資産保全を優先して状態を見直します。

### データとAI支援

- 市場・企業情報を取り込み、時系列データとして保存・参照する基盤を備えます。
- AIは市場コンテキストの分析、状態評価、事後レポートを補助します。
- AI応答だけに実行可否を委ねず、実行経路と分析経路を分離します。

### リスク管理と運用安全性

- 異常時に新規実行を抑止するキルスイッチと、状態を記録する監査設計を備えます。
- 生活資金を含む銀行残高は、運用判断の対象と区別して扱います。
- シークレットをソースコードに保存せず、実行時に安全な管理境界から取得します。
- 重要な状態変化やエラーを記録し、運用者が確認できるようにします。

具体的な戦略名、銘柄選定、シグナル、評価式、閾値、配分計算、注文処理、バックテスト結果は、戦略的優位性と安全性を守るため非公開です。

## 公開版に含まれる技術

### Frontend

- **言語/フレームワーク**: Next.js 16 / React 19 / TypeScript
- **スタイリング**: CSS Modules
- **可視化**: Recharts
- **画面**: ポートフォリオ、分析、監視、レポート、タイムライン
- **API境界**: サーバー側APIプロキシにより、ブラウザと外部サービス接続を分離

### Backend

- **言語/フレームワーク**: Python 3.11 / FastAPI / Pydantic
- **ORM**: SQLAlchemy 2.0
- **タスクスケジューリング**: APSchedulerを用いた時間ベースの処理設計
- **データ処理**: pandasおよび市場データ連携を用いる設計
- **共通基盤**: 設定読込、サーバー側認可、レート制限、構造化ログ、コスト保護

### データベース

- **ローカル開発**: SQLite
- **時系列・本番運用**: PostgreSQL 15 / TimescaleDB
- **マイグレーション**: Alembicを用いる設計

### AI・外部連携

- **AI**: 市場コンテキスト分析、状態評価、事後レポートの補助
- **市場・企業データ**: 証券APIおよび市場データサービスと連携する設計
- **銀行情報**: 銀行APIを通じた資産情報の参照設計
- **通知**: 運用状態・異常・処理結果を通知チャネルへ連携する設計

### インフラ・セキュリティ

- **実行環境**: Windows / Podman / docker-compose
- **コンテナ**: PostgreSQL / TimescaleDB、FastAPI、Next.jsの分離構成
- **ネットワーク**: localhost限定のポート公開
- **シークレット管理**: AWS Systems Manager Parameter Store / KMS
- **安全設計**: 実行経路とAI分析を分離し、認証値をソースコードへ持ち込まない方針

## セキュリティと運用ルール

実システムでは、資産を扱う経路に次の安全原則を適用しています。

1. **`TRADE_MODE=REAL` の無断切替禁止**
   仮想取引から実運用への切替は、運用者の明示的な確認なしには行わない設計です。
2. **APIキー等の平文埋め込み禁止**
   認証情報をソースコードへ直接記述しません。実運用ではAWS Systems Manager Parameter StoreとKMSを用いて実行時に取得し、開発時もローカル環境変数としてリポジトリ外で管理します。
3. **キルスイッチの無断解除禁止**
   安全装置が発動した後の復旧は、自動的に行わず、運用者による明示的で監査可能な操作として扱います。

### シークレットの準備

実システムでは、実取引モードを安全に管理し、認証情報をコードへ持ち込まないことを前提としています。公開版には口座接続・発注モジュール、実行時設定、`.env.example`を含めていません。そのため、公開版の利用者は実口座用の環境変数や認証情報を設定する必要がありません。

本番・開発を問わず、APIキー、トークン、パスワード、証明書をGitへcommitしてはいけません。

## 環境構築と確認 (Setup & Usage)

### 前提条件

- Windows 11 / PowerShell 5.1以上
- Python 3.11以上
- Node.js 20.9以上
- PodmanまたはDocker（DBコンテナ構成を確認する場合）
- AWS CLI（非公開の実運用環境でSSMを利用する場合のみ）

### 公開版で確認できること

公開版は、Frontendの静的解析・ビルドと、Backendの構成確認を目的にしています。実運用の起動、外部API接続、実口座への接続は行いません。

```powershell
cd frontend
npm ci
npm run lint
npm run build
```
